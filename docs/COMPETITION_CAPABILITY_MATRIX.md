# 比赛能力状态矩阵

本文用于统一区分：

1. 比赛公开版本中可以直接运行的能力；
2. 已在完整母仓中建设或测试、但不进入公开仓的能力；
3. 需要结合企业实际环境配置交付的能力；
4. 比赛后通过真实试点继续验证的战略目标。

该矩阵既用于 README、商业计划书和演示材料，也用于后续统一注册表与哈希血缘图的公开边界筛选。

---

## 状态定义

| 状态 | 定义 | 对外表达规则 |
|---|---|---|
| `PUBLIC_RUNTIME` | 比赛仓中存在，评委可直接运行或体验 | 可以表述为“当前可运行” |
| `PUBLIC_EVIDENCE` | 不一定参与运行，但可公开用于证明架构、测试或边界 | 可以表述为“已有公开证明” |
| `MOTHER_VALIDATED` | 完整母仓中已建设并完成接口或链路测试，比赛仓不开放实现 | 表述为“母仓已建设/验证，公开版未启用” |
| `ENTERPRISE_CONFIG` | 具备统一底座，需要根据客户 ERP、组织、权限或知识库配置 | 表述为“企业配置交付” |
| `PILOT_VALIDATION` | 产品逻辑和数据结构已具备，仍需真实客户量化效果 | 表述为“首批试点验证目标” |
| `PRIVATE_CORE` | 商业核心、内部治理、安全或知识产权能力 | 只公开能力边界，不公开代码和实现细节 |
| `REMOVE_OR_LEGACY` | 旧链路、影子入口、重复协议或不再使用的实现 | 不进入比赛发布包 |

## 首批企业试点验证指标

真实客户使用数据属于比赛后的市场验证阶段，不伪造、不用内部测试数据替代客户成效。

首批试点需要记录：

1. 报表上传、清洗、比对和分析耗时；
2. 单个运营管理的店铺与商品数量变化；
3. Agent 任务采用率、修改率和拒绝率；
4. Agent2 草案与 Agent3 SOP 的一次通过率；
5. 新人达到独立执行标准所需时间；
6. 资深运营带教时间；
7. 店铺调岗与离职交接时间；
8. 跨部门任务等待、阻塞和返工时间；
9. 日报、周报、月报编写和审核时间；
10. 企业 RAG 回流前后任务质量变化；
11. 客户付费、续费与扩展意愿。

## 对外声明规则

比赛材料、README、视频和答辩统一遵守：

- `PUBLIC_RUNTIME`：可以说“比赛版当前可运行”；
- `MOTHER_VALIDATED`：说“母仓已建设并测试，公开版未启用”；
- `ENTERPRISE_CONFIG`：说“具备统一底座，需要结合企业环境配置交付”；
- `PILOT_VALIDATION`：说“首批企业试点将量化验证”；
- `PRIVATE_CORE`：只说明商业边界，不展示代码、接口细节和部署实现；
- 不把内部测试结果表述为客户经营成效；
- 不因尚无客户报告而把已实现的产品能力降格为纯设想。
