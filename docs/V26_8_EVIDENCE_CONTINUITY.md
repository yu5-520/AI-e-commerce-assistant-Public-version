# V26.8 证据连续性：RAG 后续复用展示

本批基于已通过三报表 E2E、Release Hash Seal 与 ECS Candidate Smoke 的 V26.7.1（d4d55db4428d61ec5eee1d15df5875840efbeb09）。

## 本批交付

原任务详情 SOP 读取该任务产出的 V25 知识版本，并关联既有 rag_knowledge_reuse_events。逐条复算原始事件哈希后，展示结果、引用的检索回执和事件哈希；不读取其他任务独立产出的知识，不公开记录者与备注。

成功占比 = success / (success + failure + neutral)。分子、分母及事件哈希集合可展开。分母为零时不计算；失败/中性记录存在时成功占比可以为零。最多读取最新 101 条、展示前 100 条，额外一条只用于判断截断。存在未通过校验的事件时排除并显示排除数；截断样本不能称为全量统计。

读取不创建数据表、不调用模型、不修改知识状态。哈希复算证明记录内容一致性，不证明记录者判断正确。引用的检索回执尚未独立验证；成功占比不等于 RAG 因果效果，也不等于已通过 BASE/TARGET 对照评测。

## 验证与更新框架

沿用统一注册表、v26_field_authority 精确 BASE/TARGET 血缘门禁及原发布工作流。专项回归覆盖任务隔离、篡改拒绝、中性分母、无数据/零成功区别及 100 条展示边界。

- 生命周期与队列的一致性接线，观察窗口、超时、重试和预算的实际调度限制。

以上未交付项不因本批展示上线而视为完成。Java READY_NO_AUTHORITY 状态和原生产切换条件保持原有含义。

## 第二批：检索证据独立验证

SOP 现在按复用事件引用的精确检索回执，读取 V25.13 既有观测记录，分别复算观测哈希和 V25.12 回执哈希，并确认当前知识版本在 matchedRevisionIds 中。状态区分 VERIFIED、INVALID_EVIDENCE、REVISION_NOT_MATCHED、NOT_RECORDED，以及表尚未存在时的 NOT_CHECKED。

只为验证通过的记录展示候选数、可用数、选中数、过滤数、耗时和 `matchedCount / eligibleCount`。选中占比不是召回率；零分母不计算。原复用结果统计仍包含已验证的结果事件，不将缺少检索证明的记录静默删除；另列已核对检索的记录数量。

此批完成上述“引用检索回执的独立验证”，但尚未证明索引在生产的生效状态，也未将检索回执绑定到后续任务。仍不宣称因果效果。读取通过已有 receipt 索引按至多 100 个请求定位，每个回执最多返回最新一条观测，不扫描或公开全知识库。

## 第三批：索引内容与数据库索引头核对

在检索回执已验证的基础上，按其精确 indexManifestHash 读取原 V25.12 索引清单。复算清单身份、activeRevisions 的知识快照哈希与版本集合哈希，再比对索引版本、检索策略、当前任务知识版本的 contentHash。只公开当前关联知识版本及摘要，不公开整个索引中的其他知识内容。

已核对的索引单独标注 CURRENT_DATABASE_HEAD、HISTORICAL_MANIFEST 或 HEAD_NOT_RECORDED。当前数据库索引头只是读取时的数据库状态，不是历史启用日志或 ECS 生产运行身份证明；原始 builtAt 等未参与身份哈希的展示字段不作为验证依据。

本批完成“索引清单内容核对”，生产启用证明、后续任务绑定、系统审核与授权修订仍待独立验收。

## 第四批：冻结输入到后续任务的关联

Agent2 审计输入及 Agent3 公司 SOP 上下文保留原检索回执，冻结决策证据时复算回执哈希并限制命中集合不超过 100 项。已有显式公司上下文缺少回执时，不从其他上下文拼接回执。

任务快照保存与 task_sop_receipts_v26、task_knowledge_bindings_v26 关联写入共用调用方事务；重复保存幂等，事务回滚一并撤销。记录绑定 taskId、decisionReceiptHash、retrievalReceiptHash、revisionId 与关联哈希，保留历史冻结版本。任务详情读取不补写关联、不推断旧任务的引用关系。

复用事件检索已验证后，以精确回执及版本进行一次批量索引查询，每组至多读取 21 条、展示 20 条并报告截断。再次核对关联哈希、冻结决策回执和命中集合；悬空或损坏记录显示 INVALID_EVIDENCE，不作为有效关联。SOP 可展开任务编号及上述复算依据。

关系 TASK_INPUT_REFERENCED_RETRIEVAL 仅证明已保存任务的冻结输入引用了该检索。相同回执可关联多个任务，不能据此把复用事件的成功结果归因给某个任务；哈希也不是独立签名或生产身份凭证。没有实际检索回执的统一知识输入、历史任务仍显示未记录。本批不声称检索已在所有生产入口启用。

专项验证覆盖真实快照入口、事务回滚、重复写入、精确关联、损坏与悬空记录、查询次数和展示截断，以及显式上下文隔离。继续沿用原注册表、精确 BASE/TARGET 血缘门禁和发布流程。生产启用证明、系统审核修订接线及 BASE/TARGET 效果评测仍待验收。

## 第六批：复核写入、修订验收与 SOP 展示合并交付

运营复核沿原 review_task_evidence 入口，在保存原记录前冻结 taskId、reviewId、时间、决定、原复核记录哈希、当时的任务决策回执哈希和最新提交材料哈希。回执随原任务记录保存，任务快照与公共 DTO 展开同一证据；GET 不补写、不运行模型。公开展示排除复核人身份、备注和提交材料正文。校验复核原记录，拒绝跨任务引用和篡改；沿既有最近 10 条保留范围显示，不能解释为全历史审计账本。

运营复核不是 Java 系统审核，也不证明后续生命周期转换成功。systemReviewStatus 明确为 NOT_CONNECTED：当前 Java SystemReviewAuthority / LocalSubgraphRevisionAuthority 仍无已验收的生产任务调度接线。不得把 shadow/parity 验证样例装入真实任务。

现有 Agent3 修订验收入口在验证父图、范围覆盖和保留节点后，冻结节点前后哈希、结构化字段差异、变化数/未变化数、reviewHash、scopeHash 和目标图身份；证据随原 sopDecisionEvidence 进入快照及 SOP 展示。变化数 = count(beforeHash != afterHash)，保留零值、空值和字段存在性区别。没有已验收修订的任务显示未记录。该回执证明内容与范围一致性，不能单凭内容哈希证明授权来源或生产接管。

同时补齐保留节点的边关系校验：不得偷偷新增、删除或替换保留节点关联的关系；允许原关系中已重新开放节点的内容哈希更新。测试覆盖实际复核写入→快照→DTO、任务隔离与损坏、保留范围、修订差异→DTO，以及非法改边和合法改值。

## 第七批：审核结果、生命周期与修订投递意图的原子提交

ProductLifecycleAuthority.commitReview 在现有持久化文件锁与原子替换机制内，一次保存审核结果、生命周期状态和修订投递意图。调用原 SystemReviewAuthority 与 LocalSubgraphRevisionAuthority；合同必须匹配任务、观察起点和到期时间，写入必须匹配状态版本。等待时间/证据时不推进版本；审核通过回到监控，调整时保存 PENDING 修订范围。相同请求重试返回已提交结果，重启恢复保留同一回执。只保留最近一次提交，不声称完整历史账本。

replayReviewDispatch 经原 INVOCATION 根绑定适配器检查，将持久化 revisionHash 用作队列工作身份和输入身份。重复投递由现有 QueueAuthority 去重。此入口仍服务 Java 内存队列适配器，review:* 版本是审核工作项身份，尚未绑定生产报表/Artifact 输入。因此不持久化投递确认；下一轮观察在 PENDING 意图未获持久化接收确认时拒绝推进，防止静默丢失。生产消费者需进一步完成真实 Artifact 绑定、持久化接收、确认及代际校验接线后才能启用。

新增断言直接并入已有 V267CloseoutMain，由原 V26 权限工作流与生产包验证脚本共同执行。验证等待不变更、落盘恢复、同请求重试、旧版本拒绝、审核/调整结果原子保存、队列重复抑制、缺少权限令牌拒绝，以及内存入队不能被当作持久化确认。没有开启 Java 生产权限，也没有把 PENDING 表示成已交付。
